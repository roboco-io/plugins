# Intent Engineering Skill

프로젝트의 의도를 문서화하고, 탐구와 학습을 통해 진화시키는 스킬. 의도는 한 번 적는 것이 아니라 반복 학습을 통해 수렴하는 것이다. 수렴이 안 되면 종료하는 것도 좋은 결정이다.

사용자가 템플릿을 직접 채우면서 자기 의도를 정리하도록 돕는다. AI가 대화로 유도하지 않는다 — 사용자가 쓰고, AI는 구조만 제공한다.

## 핵심 원칙

- **How를 쓰지 않는다.** 구현 방법은 AI가 결정한다. Intent Document에는 의도만 담는다.
- **템플릿 기반.** 각 단계에서 템플릿을 제공하고 사용자가 채운다. AI가 즉흥적으로 질문하지 않는다.
- **최소한만 남긴다.** 불필요한 섹션, 장식, 메타데이터 없이 핵심만.
- **모르는 것은 모른다고 남긴다.** 확신이 없는 부분에 `(?)` 표시를 권장한다. 의도는 학습으로 명확해진다.
- **배운 것은 쌓지 않고 고쳐 쓴다.** 의도의 진화란 INTENT.md에 학습 로그를 추가하는 것이 아니라 Why/What/Not 자체를 지속적으로 수정하는 것이다. INTENT.md는 언제나 "지금의 의도"만 담는다. 무엇을 배워서 왜 바꿨는지는 git 커밋 메시지에 남기고, 변화의 이력은 `git log -p INTENT.md`로 본다. Learnings 같은 로그 섹션을 만들지 않는다.

## 의도의 생명주기

의도는 네 가지 상태를 거친다:

```
seed → exploring → clarified → (구현)
  │        │            │
  └────────┴────────────┴──→ dropped
```

**seed** — 씨앗. "이런 걸 만들면 좋겠다" 수준. Why만 있고 What/Not은 흐릿하거나 없다.

**exploring** — 탐구 중. 프로토타입, 경쟁사 조사, 사용자 인터뷰 등으로 가설을 검증한다. 매 탐구가 끝나면 결과에 맞춰 Why/What/Not을 고쳐 쓴다. What이 구체화되고 Not이 발견되며, 고쳐 쓰는 폭이 점점 줄어드는 것이 수렴의 신호다.

**clarified** — 명확해짐. Why/What/Not이 모두 확신으로 채워짐. 본격 구현으로 넘어갈 수 있다.

**dropped** — 종료. 탐구 결과 의미가 없다고 판단. 또는 이미 있는 솔루션으로 충분하다고 판단. 왜 종료했는지를 커밋 메시지에 남기면 같은 실수를 반복하지 않는다.

## 실행 흐름

### 기존 INTENT.md가 있는 경우

1. 기존 INTENT.md를 읽는다
2. 현재 status를 확인한다
3. 사용자에게 무엇을 하고 싶은지 물어본다 (AskUserQuestion 사용):
   - **탐구 결과 반영** — 배운 것을 바탕으로 Why/What/Not을 고쳐 쓴다 (아래 "탐구 결과 반영 시")
   - **섹션 수정** — Why/What/Not 중 수정할 섹션 선택
   - **상태 전이** — 다음 단계로 이동 (예: exploring → clarified, 또는 → dropped)
4. 선택에 따라 해당 템플릿을 제시하거나 상태를 전이한다
5. 변경 이유(무엇을 배워서 왜 바꿨는지)를 커밋 메시지에 남기도록 안내한다

기존 INTENT.md에 `## Learnings` 섹션이 남아 있으면, 각 항목이 Why/What/Not에 이미 반영되었는지 사용자와 확인한 뒤 반영되지 않은 내용은 해당 섹션을 고쳐 쓰고 Learnings 섹션을 삭제하도록 제안한다. 기록 자체는 git 이력에 남아 있으므로 잃지 않는다.

### 새로 시작하는 경우

#### Step 1: 상태 판별

사용자의 프롬프트에서 의도의 명확도를 파악하고 시작 상태를 제시한다. AskUserQuestion 도구를 사용한다.

- **seed** — 아이디어만 있고 구체적인 것은 없다. Why 템플릿(explore)만 채운다.
- **exploring** — 어느 정도 방향은 있지만 검증이 필요하다. Why/What/Not 템플릿을 모두 채운다.
- **clarified** — 만들 것이 확실하다. PR-FAQ 스타일로 Why를 작성하고 What/Not을 채운다.

#### Step 2: Why 템플릿 제공

상태에 따라 적절한 템플릿을 제시한다.

- seed / exploring → `templates/why-explore.md` 사용
- clarified → `templates/why-commit.md` 사용

사용자가 채운 내용을 받으면 다음 단계로 진행한다. 부족하더라도 AI가 보충하지 않는다. 사용자의 표현 그대로 존중한다.

#### Step 3: What 템플릿 제공

`templates/what.md`를 읽어서 사용자에게 제시한다.

seed 상태에서는 "지금은 비워둬도 됩니다. 탐구하면서 채워나가세요"라고 안내한다.
exploring 상태에서는 "확인하고 싶은 것 하나만 써도 충분합니다"라고 안내한다.

#### Step 4: Not 템플릿 제공

`templates/not.md`를 읽어서 사용자에게 제시한다.

"지금 당장 떠오르는 것만 적어도 됩니다. 탐구하면서 추가할 수 있습니다"라고 안내한다.

#### Step 5: INTENT.md 생성

사용자가 채운 섹션을 조합하여 프로젝트 루트에 `INTENT.md`를 생성한다.

파일 구조:

```markdown
# INTENT — [프로젝트명]

> status: seed | exploring | clarified | dropped

## Why

[사용자가 채운 내용 그대로]

## What

[사용자가 채운 내용 그대로. seed에서는 비어있을 수 있다]

## Not

[사용자가 채운 내용 그대로. seed에서는 비어있을 수 있다]
```

Learnings 같은 학습 로그 섹션은 만들지 않는다. 생성 후 첫 커밋 메시지에 시작 상태와 배경을 남기도록 안내한다.

#### Step 6: CLAUDE.md 연동

Not 섹션에서 코딩 규칙에 해당하는 항목(기술 제약, 코드 컨벤션 등)을 추출하여, 프로젝트의 CLAUDE.md에 `## Intent Constraints` 섹션으로 추가하거나 업데이트한다.

CLAUDE.md가 없으면 생성한다. 이미 있으면 해당 섹션만 교체한다.

사용자에게 추가할 내용을 보여주고 확인을 받은 후 적용한다.

### 탐구 결과 반영 시

사용자가 탐구 결과를 의도에 반영하고 싶을 때 `templates/evolve.md` 템플릿을 제시한다. 이 템플릿은 "무엇을 배웠는가"와 함께 "그래서 Why/What/Not의 어느 줄이 어떻게 바뀌는가"를 채우게 한다.

1. 사용자가 적은 "바뀌는 의도"에 따라 Why/What/Not의 해당 줄을 직접 수정한다. 사용자의 표현을 그대로 쓰고, AI가 내용을 보충하지 않는다.
2. 더 이상 맞지 않는 가설·항목은 주석이나 취소선으로 남기지 말고 삭제하거나 새 문장으로 교체한다. 과거 버전은 git 이력이 보존한다.
3. 확신이 생긴 줄에서는 `(?)`를 제거하고, 새로 불확실해진 줄에는 `(?)`를 붙인다.
4. 세 섹션 모두 "변경 없음"이면 INTENT.md를 수정하지 않는다. 그 결과는 아직 의도에 영향을 주지 않는 것이다.
5. 수정한 diff를 보여주고, 탐구와 결과를 요약한 커밋 메시지를 제안한다. 형식 예:

```
Why: 분석 대시보드에서 미수금 추적으로 피벗

SMB 5곳 인터뷰. 5곳 모두 미수금을 최우선 문제로 꼽았고
분석 기능을 요청한 곳은 없었다.
```

커밋 제목은 바뀐 섹션(Why/What/Not/status)으로 시작해, `git log --oneline INTENT.md`만 봐도 의도의 변천을 읽을 수 있게 한다.

### 상태 전이 시

상태 전이는 사용자가 결정한다. AI는 전이 조건을 안내만 한다.

- **seed → exploring**: 첫 번째 탐구(프로토타입, 조사, 인터뷰)를 시작했을 때
- **exploring → clarified**: Why/What/Not이 모두 확신으로 채워지고 `(?)` 표시가 없을 때
- **→ dropped**: 탐구 결과 의미가 없거나, 이미 있는 솔루션으로 충분할 때

상태 전이도 INTENT.md의 status 줄을 고치는 변경이며, 전이 근거는 커밋 메시지에 남긴다. dropped로 전이할 때는 종료 사유와 발견한 대안 솔루션을 커밋 메시지 본문에 기록한다. INTENT.md의 Why/What/Not은 종료 시점의 의도 그대로 둔다.

## 템플릿 파일 위치

모든 템플릿은 이 스킬의 `templates/` 디렉토리에 있다:

- `templates/why-explore.md` — seed/exploring용 Why 템플릿
- `templates/why-commit.md` — clarified용 Why 템플릿
- `templates/what.md` — What 템플릿
- `templates/not.md` — Not 템플릿
- `templates/evolve.md` — 탐구 결과를 Why/What/Not 수정으로 옮기는 템플릿
